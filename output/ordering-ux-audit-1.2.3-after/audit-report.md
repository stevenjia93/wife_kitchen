# 点菜流程 UX 审查与改进记录

审查日期：2026-08-30

## 结论

1. 餐次状态原先只有“待定/跳过/已安排”，无法表达“今天已过时间但无需补填”。现在新增仅对今天生效的“已过”状态，并提供“补记”与“不补记了”的可逆操作。
2. 原先确认下单后仅显示短暂提示，缺少状态变化和下一步。现在提交后切换到独立确认页，明确展示通知时间、餐次状态，并提供“去厨房”和“继续修改菜单”。
3. 原先下厨房详情受访问验证影响时会返回空步骤，页面只能提示复制链接。现在由阿里云千问补齐结构化原料与步骤；模型不可用时仍提供小程序内家庭参考步骤，来源链接降为可选项。
4. 视觉上保留现有暖白、黑、绿色和金色体系；通过状态标签、独立确认页与更清晰的主次按钮改善层级，没有引入新的视觉语言。

## 流程健康度

1. 选择今天餐次 — 健康：早餐/午餐/晚餐状态可辨，已过餐次不阻塞下单，可主动补记。
2. 确认下单 — 健康：提交后进入确认状态，下一步明确，可返回修改。
3. 厨房查看许愿菜 — 健康：卡片内展示原料和步骤摘要，可打开完整小程序做法。
4. 外部来源 — 健康：下厨房仅作为参考来源，不再是完成做菜流程的必经路径。
